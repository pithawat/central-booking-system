# ระบบจองรถและห้องประชุมองค์กร

เว็บแอปเดียวที่รวม 2 ระบบ: **จองรถ** (รับ-คืนกุญแจที่ป้อม รปภ. ด้วย QR หรือรหัส 4 หลัก) และ **จองห้องประชุม** (ตารางห้องว่าง + อนุมัติโดยหัวหน้าผ่านอีเมล)
สร้างด้วย Next.js 16 (App Router), React 19, Tailwind CSS 4 และ shadcn/ui · รายละเอียดทั้งหมดอยู่ที่ [docs/SPEC.md](docs/SPEC.md), flowchart ของแต่ละหน้าอยู่ที่ [docs/FLOWCHARTS.md](docs/FLOWCHARTS.md) และการตัดสินใจระหว่างพัฒนาอยู่ที่ [docs/DECISIONS.md](docs/DECISIONS.md)

## ติดตั้งและรัน

ต้องมี Node.js 20.9 ขึ้นไป (แนะนำ 24 LTS) และ pnpm ผ่าน Corepack

```bash
corepack enable
pnpm install
cp .env.example .env.local      # แล้วแก้ค่าตามตารางด้านล่าง
pnpm dev                        # http://localhost:3000
```

ถ้าเครื่องใช้ pnpm ล่าสุดไม่ได้ ให้เรียกผ่าน `corepack pnpm@10.11.0 <คำสั่ง>` (บน Windows มี `.tools/pnpm.cmd` ให้ใช้)

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `pnpm dev` | รันโหมดพัฒนา |
| `pnpm build` แล้ว `pnpm start` | รันแบบ production |
| `pnpm lint` / `pnpm typecheck` | ตรวจโค้ด |
| `pnpm test` | unit test (Vitest) |
| `pnpm test:e2e` | e2e test (Playwright) ต้องเปิดแอปไว้ที่ `http://localhost:3100` ก่อน เช่น `pnpm build && pnpm start -p 3100` |
| `pnpm check:colors` | ตรวจว่าไม่มีสีแดงในโค้ด |

> ถ้าหน้าตาหลัง `pnpm build` ไม่ตรงกับโค้ดล่าสุด ให้ลบโฟลเดอร์ `.next/cache/turbopack` แล้ว build ใหม่

### ตัวแปร env

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `DATA_SOURCE` | `mock` | `mock` = ข้อมูลจำลองในหน่วยความจำของ server, `api` = เรียก REST API จริง |
| `API_BASE_URL` | `http://localhost:4000/api/v1` | ที่อยู่ backend (ใช้เมื่อ `DATA_SOURCE=api`) |
| `API_TIMEOUT_MS` | `10000` | timeout ของการเรียก API |
| `MOCK_LATENCY_MS` | `250` | หน่วงเวลาจำลองของ mock service |
| `AUTH_MODE` | `mock` | `mock` = เลือกผู้ใช้ทดสอบ, `sso` = ล็อกอินองค์กร (ยังเป็น stub) |
| `SESSION_SECRET` | – | secret สำหรับเซ็น cookie session อย่างน้อย 32 ตัวอักษร |
| `MAIL_MODE` | `mock` | `mock` = เก็บอีเมลไว้ที่ `/dev/mailbox`, `smtp` = ส่งจริง |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` | – | ค่าของ SMTP เมื่อ `MAIL_MODE=smtp` |
| `QR_TOKEN_SECRET`, `APPROVAL_TOKEN_SECRET` | – | secret ของ QR รับรถและลิงก์อนุมัติ (โหมด mock) อย่างน้อย 32 ตัวอักษร |
| `APP_BASE_URL` | `http://localhost:3000` | ที่อยู่ของแอป ใช้สร้างลิงก์ในอีเมล ต้องตรงกับที่เปิดแอปอยู่ |
| `NEXT_PUBLIC_APP_NAME` | `ระบบจององค์กร` | ชื่อแอปบนหัวหน้าจอ |
| `NEXT_PUBLIC_ENABLE_CARS` / `NEXT_PUBLIC_ENABLE_ROOMS` | `true` | ปิดระบบรถหรือห้องทั้งระบบ (เมนู การ์ด และหน้าจะหายไป) |

### รูปรถจริง

ข้อมูลทดสอบมีรูปครบ 12 คันแล้ว (ที่มาและสัญญาอนุญาตดู `public/cars/CREDITS.md`) ถ้าจะเปลี่ยนเป็นรูปรถของบริษัท ให้วางรูปไว้ที่ `public/cars/` (เช่น `public/cars/CAR-12.jpg`) แล้วใส่ `"photoUrl": "/cars/CAR-12.jpg"` ของรถคันนั้นใน `src/shared/data/mock/seed/cars.ts` (โหมด api ให้ backend ส่ง `photoUrl` มากับข้อมูลรถ) ใช้รูปแนวนอนอัตราส่วนประมาณ 4:3 หรือ 16:9 ถ้าไม่มีรูประบบจะแสดงภาพวาดตามประเภทรถ

กฎธุรกิจที่เป็นตัวเลข (เวลา, ระยะเตือน, ขนาดช่อง ฯลฯ) อยู่ที่ `src/shared/config/app.config.ts` ที่เดียว

## สคริปต์ demo

ใช้ 2 หน้าต่าง (หรือหน้าต่างไม่ระบุตัวตน) แทนมือถือผู้จองกับแท็บเล็ตป้อม ก่อนเริ่มให้กด **เครื่องมือทดสอบ → รีเซ็ตข้อมูลทดสอบทั้งหมด** (ปุ่มลอยมุมซ้ายล่าง) อีเมลทั้งหมดดูได้ที่ `/dev/mailbox`

**ระบบรถ**
1. **รับกุญแจด้วย QR** — หน้าต่าง 1 ล็อกอินเป็น *สมชาย* เห็นบัตรรับรถ #12 รหัส 4827 · หน้าต่าง 2 ล็อกอินเป็น *แท็บเล็ตป้อม ประตู 1* → เลือกป้อม → *สมศักดิ์ มั่นคง* PIN `1234` → สแกน QR หรือพิมพ์ 4827 → "มอบกุญแจ" · ภายใน 10 วินาทีบัตรของสมชายเปลี่ยนเป็น "กำลังใช้รถ #12"
2. **คืนรถ** — สมชายกด "คืนรถ" กรอกเลขไมล์ 45,260 → ที่แท็บเล็ตแตะ #12 ใน "รถที่ออกอยู่" → "รับกุญแจคืน"
3. **เกินเวลาคืน** — #03 ของอรุณีอยู่บนสุดของ "รถที่ออกอยู่" พร้อมป้ายส้ม
4. **กุญแจยังไม่คืน แล้วสลับรถ** — เลื่อนเวลา +15 นาที 2 ครั้ง → พิมพ์รหัส 3356 (มานี) → เลือกรถคันอื่น → "มอบกุญแจ"
5. **ไม่มารับรถ** — พิมพ์ 3091 จะได้ "ยังไม่ถึงเวลารับรถ" · เลื่อนเวลาจนเลยเวลาเริ่ม 30 นาที → "รันงานตามเวลาตอนนี้" → การจองเป็น "ไม่มารับรถ"
6. ล็อกอินเป็น *นภัสสร* (ผู้ดูแลระบบ) เปิด "รายงานกุญแจ" เพื่อดู พิมพ์ หรือดาวน์โหลด CSV

**ระบบห้องประชุม**
1. **จองและอนุมัติผ่านอีเมล** — สมชายเปิด "จองห้องประชุม" แตะช่องว่างของ 2/4 ห้อง 402 → พิมพ์เรื่องที่ประชุม → "ส่งขออนุมัติ" (บล็อก "รออนุมัติ" ขึ้นทันที) · เปิด `/dev/mailbox` เลือกผู้รับเป็นวิชัย → กด "อนุมัติ" ในอีเมล → หน้ายืนยันยังไม่เปลี่ยนสถานะจนกว่าจะกดปุ่ม → สมชายได้อีเมลพร้อม `invite.ics`
2. **ไม่อนุมัติในแอป** — ล็อกอินเป็น *วิชัย* → เมนู "รออนุมัติ" → "ไม่อนุมัติ" คำขอ Sprint Review พร้อมเหตุผล
3. **คำขอหมดอายุ** — เลื่อนเวลาจนเลย 14:00 ของวันนี้ → คำขอของมานีเป็น "หมดอายุ"
4. **อนุมัติอัตโนมัติ** — ล็อกอินเป็น *ดารณี* (ไม่มีหัวหน้า) → จองแล้วอนุมัติทันที
5. **กันการจองชน** — สองหน้าต่างเปิดแผงจองช่องเดียวกัน คนที่ส่งทีหลังจะเห็น "มีคนเพิ่งจองช่วงนี้ไป เลือกเวลาอื่น"

## เปลี่ยนไปใช้ API จริงและ SSO

- ตั้ง `DATA_SOURCE=api` และ `API_BASE_URL` หน้าจอไม่ต้องแก้ เพราะทุกหน้าเรียกผ่าน `getServices()` ซึ่งสลับไปใช้ `src/shared/data/api` ให้เอง
- backend ต้องมี endpoint ตามสัญญา REST ในหัวข้อ 7.3 ของ `docs/SPEC.md` (JSON, เวลาเป็น ISO 8601 UTC, error เป็น `{ "error": { "code", "message" } }`) และต้องรับผิดชอบการออก QR token/รหัส 4 หลัก การตรวจเวลาชน การส่งอีเมลและไฟล์ .ics งานตามเวลา และการตรวจสิทธิ์
- ทุก response ถูกตรวจด้วย zod schema ใน `src/shared/data/schemas.ts`
- SSO: ตั้ง `AUTH_MODE=sso` แล้ว implement `src/shared/auth/sso-provider.ts` (เช่น Microsoft Entra ID) ให้ใส่ access token ลงใน session ระบบจะส่ง `Authorization: Bearer <token>` ให้ backend เอง ถ้าใช้ `AUTH_MODE=mock` ร่วมกับ api ระบบจะส่ง `X-Mock-User-Id` แทน

## ตั้งแท็บเล็ตที่ป้อม รปภ.

- **ต้องเปิดผ่าน HTTPS** เพราะเบราว์เซอร์อนุญาตให้ใช้กล้องเฉพาะ HTTPS หรือ localhost (ถ้าเปิดกล้องไม่ได้ ช่องพิมพ์รหัสยังใช้ได้ตามปกติ)
- ใช้แนวนอน (1024–1366px) ล็อกอินเป็นผู้ใช้ "แท็บเล็ตป้อม" แล้วเลือกป้อมครั้งแรกครั้งเดียว (เครื่องจะจำไว้ 1 ปี)
- ล็อกหน้าจอไว้ที่แอป: Android ใช้ "ปักหมุดหน้าจอ" (Screen pinning) / iPad ใช้ "การเข้าถึงที่ได้รับการชี้นำ" (Guided Access)
- ตั้งความสว่างหน้าจอให้สูงพอสำหรับสแกน QR และเสียบสายชาร์จไว้ตลอด (แอปขอให้หน้าจอไม่ดับเองด้วย Wake Lock)

## หมายเหตุโหมด mock

ข้อมูล mock อยู่ในหน่วยความจำของ server ทุกเครื่องจึงเห็นข้อมูลชุดเดียวกัน แต่ต้องรันบน **server เดียว** (`pnpm build && pnpm start` หรือ Docker) ไม่เหมาะกับ serverless และข้อมูลจะหายเมื่อรีสตาร์ต ชื่อคน อีเมล และเบอร์โทรใน mock เป็นข้อมูลสมมติทั้งหมด
