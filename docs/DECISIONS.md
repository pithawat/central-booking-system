# การตัดสินใจในการพัฒนา

- ใช้ Next.js 16.4.0 จาก create-next-app ล่าสุดตามข้อ 3.1 และปิด cacheComponents
- เครื่องมี Node.js 20.11.1 (ผ่านขั้นต่ำ 20.9) และ Corepack 0.23; ใช้ pnpm 10.11.0 เพราะ pnpm ล่าสุดไม่ทำงานบนเครื่องนี้ มีตัวเรียก .tools/pnpm.cmd สำหรับ Windows
- create-next-app สร้างไฟล์สำเร็จแต่ติดตั้งไม่ได้เพราะไม่มี pnpm ใน PATH จึงย้าย scaffold มา root และติดตั้งต่อด้วย Corepack; AGENTS.md ใช้ต้นฉบับจากแพ็กเกจ next
- อ่านเอกสาร Next.js ที่ติดตั้งเกี่ยวกับ cookies, Server Actions และ proxy ก่อนพัฒนา รวมถึง https://nextjs.org/docs/app/guides/upgrading/version-16
- พอร์ต 3000 ถูกใช้งานโดยโปรเซสอื่น จึงทดสอบบน 3100 และตั้ง APP_BASE_URL ให้ตรงกัน; Vitest 3 + Vite 6 รองรับ Node.js ในเครื่อง
- Phase 0 ผ่าน unit test 6 ข้อและ Playwright ล็อกอินครบ 6 คน, redirect, mailbox, ฟอนต์, เลื่อนและรีเซ็ตเวลา; ไม่มี backend จริงตามขอบเขต ส่วน mutation รถ/ห้องจะเติมใน Phase 1/2

- เพิ่มข้อมูลอ่านอย่างเดียว nextBookingStart? ใน CarBookingDetail เพื่อปิดตัวเลือกขยายเวลาที่ชนโดยไม่ต้องเรียก availability หลายสิบครั้ง (availability เดิมถือ IN_USE ไม่ว่างเสมอ) endpoint เดิมคงเดิม; backend ควรส่งฟิลด์นี้เมื่อเชื่อมจริง และ service ยังตรวจชนซ้ำทุกครั้ง
- Phase 1: scenario A–E ผ่าน service tests รวม QR token, เลขไมล์, เปลี่ยนรถ, no-show, อีเมลครั้งเดียว และ e2e A/B สอง session ผ่าน

## Phase 2 · ระบบจองห้องประชุม
- mock service ของห้อง, งานตามเวลา และ template อีเมลมีอยู่แล้วตั้งแต่ Phase 1 รอบนี้เพิ่มหน้าจอทั้งหมด, route `.ics` และ unit test ส่วนห้อง (14 ข้อ) รวม service test ของ scenario F–J
- `formatDate`/`formatDateLong`/`formatRange` ใช้ตารางชื่อวันและเดือนภาษาไทยที่เขียนเอง แทน `Intl` ตามหัวข้อ 5.4 เพราะ ICU ของ Node กับ Chrome ย่อชื่อวันพฤหัสบดีไม่เหมือนกัน ("พฤ." กับ "พฤหัส") ทำให้ client component hydrate ไม่ตรง ผลลัพธ์ยังตรงตาม spec (`พ. 7 ต.ค. 2026`, `วันพุธที่ 7 ตุลาคม 2026`, BE = +543)
- การตัดสินผ่านลิงก์อีเมล (`decideRoom` แบบ token) ไม่เรียก `revalidatePath` เพื่อให้หน้า `/approve/[token]` แสดง "อนุมัติแล้ว ระบบแจ้งผู้จองทางอีเมลแล้ว" ในที่เดิม ถ้าเปิดลิงก์ซ้ำจะเห็น "อนุมัติแล้วเมื่อ …"
- ช่อง "ผู้ใช้งานห้อง" เป็นช่องค้นหา + รายการผลลัพธ์ (role combobox/listbox) ภายใน Collapsible แทน Popover+Command เพื่อให้ช่องกรอกสูง 48px ตามหัวข้อ 11.3 เมื่อเลือกคนอื่น เบอร์ติดต่อเปลี่ยนเป็นของคนนั้นและยังแก้ได้
- ตัวกรองฝั่ง "ทั้งหมด" ใช้ค่า `site=all` ใน URL ถ้าไม่มี `site` จะใช้ `defaultSiteId` ของผู้ใช้
- การ์ดห้องบนมือถือ (และมุมมองวันของห้องเดียว) แสดง "รายการจอง" ของวันนั้นเพิ่มใต้ชิปช่วงว่าง เพื่อให้แตะดูหรือยกเลิกการจองของตัวเองบนมือถือได้
- หน้า `/rooms` และ `/rooms/[roomId]` ใช้ `useAutoRefresh` ระหว่างที่ไม่ได้เปิดแผงจอง เพื่อให้เห็นการจองของคนอื่นโดยไม่ต้องโหลดหน้าใหม่
- ปุ่ม "เพิ่มลงปฏิทิน" แสดงเฉพาะการจองที่อนุมัติแล้วและยังไม่จบ ส่วน route `.ics` คืน 404 ถ้ายังไม่อนุมัติ
- unit test ที่ส่งหัวข้อว่างคาด `ZodError` จาก service เพราะ service ใช้ zod ตรวจตรง ๆ แล้ว server action แปลงเป็น `VALIDATION` พร้อมข้อความใต้ช่องกรอก
- ผลตรวจ Phase 2: F (service + e2e), G, H, I, J ผ่าน unit test; K ตรวจด้วย `next start` ที่ตั้ง `NEXT_PUBLIC_ENABLE_ROOMS=false` และ `NEXT_PUBLIC_ENABLE_CARS=false` แยกกัน เมนู การ์ด และหน้าของระบบที่ปิดหายไป (หน้า not found ส่งสถานะ 200 เพราะ `loading.tsx` เริ่ม stream ก่อน ซึ่งเป็นพฤติกรรมปกติของ Next.js 16)

## Phase 3 · เก็บงาน และปรับ UI
- ปรับหน้าตาให้ทันสมัยขึ้นโดยไม่แตะ token สีในหัวข้อ 11.2: เพิ่มพื้นหลังเนื้อหา `--canvas` (#f5f7fb), เงาการ์ด และ utility `surface`/`surface-interactive` ใน `globals.css`; AppShell มีโลโก้และแถบเมนูแบบ pill พร้อมเส้นใต้ของเมนูที่ใช้งาน; หน้าแรกมีส่วนหัว gradient โทนน้ำเงิน; หน้า login แบ่งสองฝั่ง
- แก้ขนาดคอมโพเนนต์ shadcn ที่ยังไม่ตรงหัวข้อ 11.3: Input/SelectTrigger/Toggle/Tabs สูง 48px, ปุ่มปิด Sheet/Dialog 48px, ตัวอักษร Textarea/Alert/Badge/toast ไม่ต่ำกว่า `text-sm`; Toaster บังคับ theme สว่าง
- ช่องเวลาที่ผ่านไปแล้วในตารางห้องใช้ลายเส้นทแยงสีเทา (`.slot-past`) ให้เห็นชัดกว่าพื้นเทาอ่อน
- แผงจอง/รายละเอียดคืน focus ไปที่ช่องหรือบล็อกที่เปิดแผงเมื่อปิด (ตรวจด้วยคีย์บอร์ดล้วน)
- เพิ่ม `loading.tsx` (skeleton), `error.tsx` และ not-found ภาษาไทยในทุกส่วนหลัก, `(public)/layout.tsx` สำหรับหน้าอนุมัติ และ `(station)/guard/layout.tsx`
- e2e: scenario A (เดิม), F และการตรวจว่าไม่มีการเลื่อนแนวนอนทั้งหน้าที่ 375/768/1024/1366/1440px; แก้ e2e ของ Phase 0 ให้ตรงกับขั้น "เลือกป้อม" ที่เพิ่มใน Phase 1
- build ของ Turbopack เคยใช้ CSS เก่าจาก `.next/cache/turbopack` ถ้าหน้าตาหลัง build ไม่ตรงโค้ดให้ลบโฟลเดอร์นั้นแล้ว build ใหม่ (บันทึกไว้ใน README)

## ปรับหน้าแท็บเล็ต รปภ. ให้เข้าใจง่ายขึ้น
- แยกไฟล์ตามโครงสร้างหัวข้อ 5.1: `station-picker`, `shift-login`, `result-panel`, `board-lists` ส่วน `guard-screen` เหลือแค่ควบคุมสถานะ ข้อความและลำดับขั้นตามหัวข้อ 8.5 คงเดิมทั้งหมด
- หน้าหลักวางกล้องกับแป้นตัวเลขคู่กัน (มีคำว่า "หรือ" คั่น) ด้วย container query เพื่อให้เห็นครบโดยไม่ต้องเลื่อนที่ 1024–1366px ภาพกล้องจะแคบลงเมื่อพื้นที่น้อย ซึ่งไม่กระทบการอ่าน QR เพราะอ่านจากวิดีโอเต็มความละเอียด ถ้าแคบกว่า 440px จะเรียงลงล่างและกล้องสูง 288px
- แผงผลลัพธ์แยกสีตามชนิด: เขียว = ตรงกับการจอง, น้ำเงิน = คืนรถ, อำพัน = ยังไม่ถึงเวลา/กุญแจยังไม่คืน, ส้ม = ไม่พบหรือใช้ไม่ได้ พร้อมไอคอนและบรรทัดอธิบายว่าต้องทำอะไรต่อ ช่องกุญแจแสดงเป็นป้ายใหญ่ หน้าสำเร็จมีแถบนับถอยหลังกลับหน้าสแกน
- รายการฝั่งขวามีบรรทัดบอกว่าแตะเมื่อไหร่ แถวที่อยู่ในช่วงรับรถมีป้าย "ถึงเวลารับ" (เดิมพื้นสีฟ้าไม่แสดงเพราะ class ชนกัน) และแถวมี aria-label รวมเลขรถ ชื่อ และเวลา
- เข้าเวรเป็น 2 ขั้น "แตะชื่อของคุณ" → "ใส่ PIN 4 หลัก" ในการ์ดเดียว
- บน PC พิมพ์ตัวเลขลงช่องรหัสได้เลยโดยไม่ต้องคลิกช่อง และ Backspace ลบได้ (หัวข้อ 8.5) ช่องเลขไมล์ของ รปภ. ไม่มี placeholder เพื่อไม่ให้ดูเหมือนกรอกแล้ว

## ปุ่มเปิด/ปิดกล้อง, หน้า รปภ. บนจอเล็ก และการขยายเวลาแบบใหม่
- เพิ่มปุ่ม "ปิดกล้อง" / "เปิดกล้อง" ในกล่องสแกน จำค่าไว้ใน `localStorage` ของเครื่อง (ค่าเริ่มต้นเปิด) เพื่อลดความร้อน แบตเตอรี่ และการสแกนโดยไม่ตั้งใจเมื่อป้อมไม่ได้ใช้ QR ระหว่างแสดงผลลัพธ์ (รวมการตรวจบัตรจากรายการ "รอรับวันนี้") กล้องหยุดเองอยู่แล้ว จึงไม่ต้องกดปิดเมื่อเปลี่ยนวิธียืนยัน
- หน้า `/guard` ใช้ได้ตั้งแต่มือถือ 375px: แก้ grid ที่ไม่มี `grid-cols-1` ทำให้คอลัมน์ขยายตามความกว้างขั้นต่ำของรายการ, ลด padding/หัวข้อ/นาฬิกาบนจอเล็ก, ซ่อนรูปในแถวรายการบนจอเล็ก, ตัวอักษรพื้นฐาน 18px ต่ำกว่า 640px (แท็บเล็ตยัง 20px ตามหัวข้อ 8.5) และเพิ่ม e2e ตรวจที่ 375/768/1024/1366px
- ขยายเวลา (หัวข้อ 8.4) เปลี่ยนจาก Select เป็นปุ่มลัด "+30 นาที / +1 ชม. / +2 ชม. / +4 ชม." และปุ่ม − / + ทีละ 30 นาที พร้อมแสดงเวลาคืนใหม่ตัวใหญ่ ตามที่ผู้สั่งงานขอ เพราะ Select มีตัวเลือกหลายร้อยรายการ (ทุก 30 นาทีของ 8 วัน) ชุดเวลาที่เลือกได้และกฎเดิมไม่เปลี่ยน: ช่วง 06:00–22:00, ไม่เกิน maxBookingDays และไม่เกินต้นการจองถัดไป ปุ่มที่เกินขอบเขตกดไม่ได้ และมีบรรทัดบอกว่าขยายได้ถึงเมื่อไหร่ ค่าเริ่มต้นคือ +1 ชม. (หรือค่าแรกที่เลือกได้)

## จองรถหลายวันเป็นหลัก, เตือนล่วงหน้า 1 วัน, รูปรถ, มือถือ, หน้า รปภ. และหน้าแรก (ตามคำขอผู้สั่งงาน ไม่เปลี่ยนขั้นตอนการทำงาน)
- หน้า `/cars` แสดงช่อง "รับรถ" (วัน + เวลา) และ "คืนรถ" (วัน + เวลา) ตลอด แทนสวิตช์ "ใช้หลายวัน" ค่าเริ่มต้นคืนรถวันถัดไป 17:00 (`appConfig.car.defaultReturn`) และมีปุ่มลัด 2 วัน / 3 วัน / 1 สัปดาห์ (`dayPresets`) ต่อจากครึ่งเช้า / ครึ่งบ่าย / ทั้งวัน · URL params และกฎเดิม (ไม่เกิน 7 วัน) ไม่เปลี่ยน · เปลี่ยนวันรับรถแล้ววันคืนเลื่อนตามเพื่อคงจำนวนวัน
- งานตามเวลาใหม่ `CAR_DAY_BEFORE_REMINDER`: อีเมลถึงผู้จอง 24 ชม. ก่อนเวลารับรถ (`reminderDayBeforeHours`) ส่งครั้งเดียว และส่งเฉพาะการจองที่สร้างก่อนจุดนั้น (จองกระชั้นชิดได้อีเมลยืนยันอยู่แล้ว) ทำเฉพาะระบบรถตามคำขอ
- `Car.photoUrl` (ไม่บังคับ) สำหรับรูปรถจริง ทั้ง type, zod schema และ seed (ค่า null) ถ้าไม่มีรูปหรือโหลดไม่ได้จะแสดงภาพวาดด้านข้างตามประเภทรถ · ป้ายทะเบียน (`LicensePlate`) เป็นข้อมูลหลักในการ์ดรถ บัตรรับรถ หน้าการจองของฉัน และหน้า รปภ. ส่วนเลขรถ (#12) ยังอยู่เป็นข้อมูลรอง เพราะ spec และช่องกุญแจใช้เลขนี้
- หน้าแรกไม่มีส่วนหัว "สวัสดี คุณ..." (ต่างจาก §10.3 ตามคำขอ) บัตรรับรถบนหน้าแรกเป็นแบบย่อ: QR ภาพเล็ก 92px แตะเพื่อเปิดเต็มจอ (Dialog เดิม) พร้อมรหัส 4 หลักตัวใหญ่ · บนจอใหญ่แบ่ง 2 คอลัมน์ (บัตร + รายการ | เมนูจอง) (ลำดับหน้าแรกเปลี่ยนอีกครั้งในหัวข้อ "หน้าแรกเริ่มที่ปุ่มจอง" ด้านล่าง)
- ปรับสำหรับมือถือ (iPhone 15, 393px): `viewportFit: cover` + safe area ของแถบเมนูล่างและแถบบน, หัวหน้าเล็กลง, ปุ่มลัดและตัวกรองเลื่อนแนวนอนได้, การ์ดรถบนมือถือเป็นแนวนอน (รูปซ้าย ข้อมูลขวา), ปุ่มยืนยันในแผงจองติดด้านล่าง, รายงานกุญแจบนมือถือเป็นการ์ดแทนตาราง (พิมพ์ยังเป็นตาราง), ปุ่มเครื่องมือทดสอบเล็กลง
- หน้า รปภ. กันการผิดพลาด (ขั้นตอนเดิมทุกอย่าง): ปุ่มหลักกดได้หลังผลลัพธ์ขึ้น 0.8 วินาที (กันนิ้วที่แตะค้าง), ปุ่ม "ยกเลิก" แยกไปทางซ้ายและเล็กกว่า, ระหว่างแสดงผลลัพธ์รายการฝั่งขวาถูกล็อก (inert), ป้ายทะเบียนและช่องกุญแจตัวใหญ่, กรอกเลขไมล์ด้วยแป้นบนจอและปุ่ม "รับกุญแจคืน" กดได้เมื่อเลขไมล์ไม่น้อยกว่าเลขล่าสุด (เตือนสีอำพันถ้าเพิ่มเกิน 2,000 กม.), ปุ่มกล้องย้ายไปอยู่ในกรอบกล้อง, ปุ่ม "เปลี่ยนเวร" เป็นปุ่มจาง

- กล้องไม่เปิดค้างอีกต่อไป: กลางจอมีปุ่มใหญ่ "สแกน QR" แตะแล้วเปิดกล้องเต็มจอ (Dialog ชั้นเดียว) ปิดเองเมื่อสแกนเจอ กด "ปิดกล้อง" / Esc หรือไม่มีการสแกน 60 วินาที ใต้ปุ่มเป็นแป้นรหัส 4 หลักเหมือนเดิม (§8.5 เดิมให้กล้องเปิดอยู่ในโหมดรอ เปลี่ยนตามคำขอเพื่อประหยัดแบตเตอรี่และกันสแกนโดยไม่ตั้งใจ) ปุ่มเปิด/ปิดกล้องแบบเดิมจึงถูกแทนที่
- รายการ "รอรับวันนี้" กับ "รถที่ออกอยู่" อยู่ในแถบด้านข้างแบบ segmented control (แท็บ) แทนการเรียงซ้อน พร้อมจำนวนและป้าย "เกิน n" บนแท็บรถที่ออกอยู่เมื่อมีรถเกินเวลา ลำดับในแต่ละรายการคงเดิม
- จัดให้ทั้งหน้าเห็นครบโดยไม่เลื่อนบน iPad แนวนอน (1180×820, 1366×1024): ลดความสูงปุ่มสแกนบนจอเตี้ย, ปุ่มแป้นตัวเลขสูง 56px (ขั้นต่ำของหน้า รปภ.)

## หน้าแรกเริ่มที่ปุ่มจอง และปรับทุกหน้าของผู้ใช้สำหรับมือถือ (ตามคำขอ ไม่เปลี่ยนขั้นตอนการทำงาน)
- หน้าแรกเรียงใหม่: **เริ่มจอง** (การ์ดใหญ่ จองรถ / จองห้องประชุม คู่กัน พร้อมวันที่) → แถบคำขอรออนุมัติ (ถ้ามี) → **สถานะการจองรถ** (บัตรรับรถแบบย่อถ้าอยู่ในช่วงรับรถหรือกำลังใช้ ไม่งั้นการ์ดการจองรถถัดไปพร้อมบอกว่า QR จะขึ้นก่อนรับรถ 30 นาที ถ้าไม่มีเลยแสดงปุ่มจองรถ) → **การจองที่กำลังจะถึง** 5 รายการ (ไม่ซ้ำกับรายการในสถานะการจองรถ) · จอใหญ่ (lg) สถานะการจองรถกับรายการอยู่คู่กัน 2 คอลัมน์ · ข้อมูลและลิงก์ทุกอย่างเหมือนเดิม
- ตรวจทุกหน้าของผู้ใช้อัตโนมัติด้วย Playwright บนมือถือ 7 รุ่น (กว้าง 320 / 360 / 375 / 393 / 412 / 430 px) ทั้งหน้าและสถานะที่เปิดแผง เมนู ปฏิทิน: ไม่มีส่วนไหนล้นจอแนวนอน (ยกเว้นแถบที่ตั้งใจให้เลื่อน เช่น แถบวัน ชิปช่วงว่าง)
- กติกากันล้นจอที่ใช้ทั้งโปรเจกต์: grid ต้องมี `grid-cols-1` เป็นค่าฐาน (คอลัมน์ `auto` ขยายตามข้อความยาวจนล้น), ข้อความที่ห้ามตัดกลาง (ช่วงเวลา ทะเบียนรถ) ใช้ `whitespace-nowrap`, ช่วงวันเวลาแยก 2 ท่อนด้วย `periodParts` / `PeriodText` ให้ตัดบรรทัดได้เฉพาะระหว่างวันที่กับเวลา, ขนาดหัวข้อ h1–h3 ย้ายเข้า `@layer base` เพื่อให้คลาส Tailwind (`text-lg` ฯลฯ) ทับได้
- `/rooms` บนมือถือ: ปุ่มวันที่เต็มความกว้าง + แถบเลือกวัน 14 วัน (วันนี้ / พรุ่งนี้ / วันในสัปดาห์) + แถวสรุปตัวกรองพร้อมปุ่ม "ตัวกรอง" · การ์ดห้องมีแถบเวลาย่อ 07:00–19:00 ให้เห็นช่วงว่างในแวบเดียว ชิปช่วงว่างเหมือนเดิม และรายการจองของห้องพับไว้ (แตะ "การจอง n รายการ" เพื่อดู) เพื่อลดความยาวหน้า · หัวอาคารติดด้านบนตอนเลื่อน
- `/rooms/[roomId]` บนมือถือ: มุมมองสัปดาห์เป็นแถบ 7 วัน (จุด = มีการจอง) แตะวันเพื่อดูการ์ดของวันนั้น เปลี่ยนสัปดาห์ด้วยปุ่ม ‹ › · มุมมองวันใช้แถบเลือกวันแบบเดียวกับ `/rooms` · จอตั้งแต่ 768px ยังเป็นตารางสัปดาห์เดิม
- การ์ดการจองรถ (หน้าแรก, การจองของฉัน): รูป + ทะเบียน + รุ่นอยู่แถวบน วันเวลาและปลายทางเต็มความกว้างการ์ด จอแคบจะได้ไม่ถูกบีบข้างรูป · การ์ดการจองห้องทั้งใบแตะเพื่อเปิดรายละเอียด ปุ่มอยู่แถบล่างของการ์ด
- แผงด้านล่าง (Drawer) บนมือถือ: แถบปุ่มยืนยันติดขอบล่างจริงและเว้นแถบโฮมของ iPhone (`safe-area-inset-bottom`) ไม่มีเนื้อหาโผล่ใต้แถบ · ตัวเลือกเวลาคืนรถในแผงขยายเวลาลดขนาดบนจอแคบ ตัวเลขเวลาไม่ตกบรรทัด
- `/rooms/approvals` บนมือถือ: แถบ "อนุมัติที่เลือก" อยู่เหนือเมนูล่าง แบ่ง 2 แถว · หน้าอนุมัติจากลิงก์อีเมลและหน้ารายละเอียดการจองห้องแสดงหัวข้อ/ค่าแบบบน-ล่างเมื่อจอแคบกว่า 400px
- ผู้ดูแลระบบบนมือถือเข้า "รายงานกุญแจ" ได้จากเมนูผู้ใช้ (แถบเมนูล่างมีที่ 4–5 ปุ่ม) · ปุ่มเครื่องมือทดสอบ (เฉพาะโหมดทดสอบ) บนมือถือเขียนว่า "ทดสอบ" และหลบขึ้นเหนือแถบปุ่มด้านล่าง · ปิด dev indicator ของ Next.js (`devIndicators: false`) เพราะทับปุ่มเครื่องมือทดสอบ
