# Flowchart การทำงานของแต่ละหน้า

เอกสารนี้สรุปการทำงานของทุกหน้าในระบบเป็นแผนภาพ อ้างอิงพฤติกรรมของโค้ดปัจจุบันและ [SPEC.md](SPEC.md) (เลขหัวข้อในวงเล็บ เช่น §8.5 คือหัวข้อใน SPEC)

แผนภาพเขียนด้วย [Mermaid](https://mermaid.js.org/) ซึ่งแสดงเป็นรูปได้เองบน GitHub / GitLab และใน VS Code (ติดตั้งส่วนเสริม "Markdown Preview Mermaid Support")

**สัญลักษณ์ที่ใช้**

| รูปทรง | ความหมาย |
|---|---|
| วงรี `([ ])` | จุดเริ่มหรือจุดจบ |
| สี่เหลี่ยม `[ ]` | หน้าจอหรือสิ่งที่ผู้ใช้เห็น / ทำ |
| สี่เหลี่ยมมุมมน `( )` | งานที่ระบบทำ (Server Action / service) |
| ข้าวหลามตัด `{ }` | เงื่อนไข |

## 1. ภาพรวม: การเข้าระบบ สิทธิ์ และ feature flag

ทุกหน้าผ่าน `proxy.ts` ก่อน (ตรวจแค่ว่ามี cookie) แล้วหน้าแต่ละหน้าตรวจสิทธิ์จริงฝั่ง server อีกครั้ง (§5.5)

```mermaid
flowchart TD
  A(["เปิด URL ใดก็ได้"]) --> B{"เป็น /login หรือ /approve/... ?"}
  B -->|"ใช่"| P["เปิดหน้านั้นได้เลย"]
  B -->|"ไม่ใช่"| C{"มี cookie session ?"}
  C -->|"ไม่มี"| L["ไป /login?next=หน้าเดิม"]
  C -->|"มี"| D{"ระบบของหน้านี้ถูกปิดด้วย<br/>NEXT_PUBLIC_ENABLE_* ?"}
  D -->|"ปิด"| NF["หน้า ไม่พบข้อมูลนี้"]
  D -->|"เปิด"| E("ตรวจ session ฝั่ง server")
  E -->|"session ไม่ถูกต้อง"| L
  E --> F{"บทบาทมีสิทธิ์เข้าหน้านี้ ?"}
  F -->|"มี"| OK(["แสดงหน้า"])
  F -->|"ไม่มี"| G{"เป็น STATION ?"}
  G -->|"ใช่"| GU["ไป /guard"]
  G -->|"ไม่ใช่"| H["ไปหน้าแรก /"]
```

| หน้า | ใครเข้าได้ |
|---|---|
| `/`, `/my`, `/cars/*`, `/rooms/*` | EMPLOYEE, ADMIN |
| `/rooms/approvals` | หัวหน้า (มีลูกน้อง) หรือ ADMIN ถ้าไม่ใช่จะถูกพาไปหน้าแรก |
| `/admin/key-log` | ADMIN |
| `/guard` | STATION |
| `/approve/[token]` | ทุกคนที่มีลิงก์ถูกต้อง ไม่ต้องล็อกอิน |
| `/dev/mailbox` | ทุกคนที่ล็อกอินแล้ว เฉพาะ `DATA_SOURCE=mock` |
